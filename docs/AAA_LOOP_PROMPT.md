# 黒猫飯店 AAA品質ループ・プロンプト

HD-2Dの最高峰と並べて見劣りしない画にするための、ファンアウト＋辛口ブラインド批評ループ用プロンプト。
`/goal` や `/loop` に貼って使う。ベンチマーク画像は `docs/Refs/bench/` に置く（後述）。

---

## フル版（これをそのまま貼る）

```
黒猫飯店（このリポジトリのHD-2Dポモドーロ経営RPG）を、HD-2Dジャンルの最高峰と
並べてブラインドで比べても勝てる画と手触りにしてほしい。一切妥協するな。

【ベンチマーク】自作と比較する対象は以下。記憶ではなく docs/Refs/bench/ の実画像で比べる。
- 絵作り全般：オクトパストラベラーII、ライブアライブ(HD-2Dリメイク)、トライアングルストラテジー
- 店・昼夜ループ・報酬演出：デイブ・ザ・ダイバー
- UIの気持ちよさ／情報密度：ペルソナ5 ザ・ロイヤル
- 湿ったネオンの夜の空気：サイバーパンク2077の夜市、ブレードランナー2049

【やり方】ultracode。以下の項目ごとにサブエージェントをファンアウトし、各項目を /loop で回す。
1つの項目につき「実装エージェント」と「批評エージェント」を必ず別人格にする。批評家は実装
してはならず、実装者の弁明を聞いてもいけない。

【審査プロトコル：ブラインドA/B】各ループで必ずこれを回す。
1. 実装エージェントが変更後の画面を撮影する。撮影は既存の型に従う：
   xvfb-run -a -s "-screen 0 760x1320x24" /tmp/Godot_v4.6-stable_linux.x86_64 \
     --rendering-method gl_compatibility --rendering-driver opengl3 --audio-driver Dummy \
     --path . -s tests/_shot_<項目>.gd
   （tools/hd2d_shot.gd と直近の tests/_shot_*.gd が参考。撮影スクリプトは使い捨てにし、
     コミット前に消すこと）
2. 進行役エージェントが、自作スクショとベンチ画像を「A」「B」にランダムに割り当てる。
   どちらが自作かは批評エージェントに絶対に伝えない。
3. 批評エージェントに問う：「AとBはどちらがAAAタイトルの画か。理由を、光・色・
   コントラスト・被写界深度・接地・情報設計・フォント・余白の観点で具体的に述べよ。
   劣る方について、何をどう直せば勝てるか、実装可能な粒度で列挙せよ」
4. 批評家が自作を選ばなかった場合は不合格。指摘を実装タスクに落として実装者に差し戻し、
   1に戻る。
5. 「自作が勝つ、または判別不能」が3ラウンド連続で出るまで止まるな。1回勝っただけで
   終わらせるのは禁止。

【項目（各1サブエージェント）】
A. ホーム（黒猫飯店）ディオラマの絵作り
   ライティングの寒暖対比、被写界深度、ブルームの締まり、光芒、湯気、床の擬似反射、
   奥行きのレイヤー分け。今は発光ボックスが白飛びしている箇所がある。
B. チビキャラのスプライト演出
   歩行・待機の手触り、リム光、接地影の説得力、キャラごとの立ち姿の差、
   ピクセル密度の統一（ここが混ざるとHD-2Dは即座に安く見える）。
C. VN窓と全UIのタイポグラフィ
   フォント、字間、余白、角丸とストロークの一貫性、アイコンの統一、
   ボタンの押し心地（押下・ホバー・無効の3状態が全部あるか）。
D. UIモーション
   画面遷移、数値のカウントアップ、トースト、シート開閉のイージング。
   ペルソナ5基準で「触って気持ちいいか」。
E. 潜航（戦闘）画面
   敵の存在感、ヒットストップ、ダメージ数字の演出、カメラシェイク、
   決着の瞬間のカタルシス。
F. 横帯フィールド（strip）
   狭い帯の中での奥行き表現、パララックス、進行感。
G. 夜営業シアター
   客の入店から着席・配膳・チップ・締めの精算まで、デイブ・ザ・ダイバー基準の
   テンポと祝祭感。ここが5分休憩の報酬なので、退屈なら失敗。
H. 経営UI（改装ツリー・市場・工房）
   一覧性、解放時の高揚、コストと効果の読みやすさ。
I. パフォーマンス
   実機PWA（モバイル）で60fps。落ちる箇所を計測で特定してから直す。
   「綺麗だが重い」は不合格。
J. 導線とオンボーディング
   初回起動から最初の25分を始めるまでに迷う箇所ゼロ。

【絶対条件】
- 既存のテスト（tests/test_sim.gd、現在223チェック）を1つも割らない。
- 各項目の完了時、ビフォー・アフターのスクショを必ず並べて提示する。
  「良くなりました」だけの報告は無効。
- ピクセル密度・ライティング方針・フォントは全画面で統一する。1画面だけ綺麗でも
  ゲーム全体では不合格。
- 絵の美しさだけで合格にするな。最終審査は「この画面を見て、いま25分の
  ポモドーロを始めたくなるか」。ならないなら、綺麗でも不合格。

【禁止】
- 批評エージェントが実装を兼ねること。
- ベンチ画像なしで「記憶上のオクトパスと比べて遜色ない」と判定すること。
  ベンチ画像が無い項目は、その旨を報告に明記した上で判定を保留する。
- 作業ツリーを汚したまま終わること。各項目の完了ごとに日本語でコミットしてプッシュする。
```

## 短縮版（気軽に回すとき）

```
ultracode。黒猫飯店の <画面名> を、オクトパストラベラーII と デイブ・ザ・ダイバー に
ブラインドで並べて勝つまで /loop で磨け。実装役と批評役は別エージェント。毎ラウンド
xvfb でスクショを撮り、ベンチ画像とA/Bをシャッフルして批評役に渡し、どちらがAAAか
理由付きで選ばせる。自作が3連続で勝つか判別不能になるまで止まるな。223チェックは割るな。
```

## 参照画像から抽出した合格基準（実画像を見た上での要件）

セッション中に提供された4枚（オクトパスIIの街／オクトパスIIの戦闘／デイブ・ザ・ダイバーの店／
ペルソナ5の戦闘UI）から、この作品に効く判定基準を抜き出したもの。批評エージェントへは
この節をそのまま渡す。

**オクトパスII（街）— ホームのディオラマが目指す絵**
- あらゆる面に素地がある。屋根瓦・石壁・木の板目まで描かれ、無地の面が存在しない
- 明確な主光源が1方向にあり、影が濃く落ちる。暖色の光と寒色の影で画面が二分される
- ティルトシフトで上端と下端がぼけ、中央の帯だけがシャープ
- 遠景は必ず沈む（暗く・ぼけ・彩度が落ちる）。手前が明るい
- 赤提灯のような小さな彩度の高い点が、視線の止まり木として置かれる

**オクトパスII（戦闘）— 潜航画面が目指す絵**
- 敵が構図の1/3以上を占め、主人公より大きい。全員が接地して影を落とす
- 夜でも青い月光と光芒があり粒子が舞う。真っ黒な平面が無い
- UIは金と羊皮紙の2色＋選択中のみ白。虹色のボタンは存在しない
- パーティのHP/SPは数値付きで縦に並ぶ

**デイブ・ザ・ダイバー — 夜営業シアターが目指す絵**
- 客が一人ひとり違う人に見える（髪・服・体格）。頭上の吹き出しに料理アイコン
- 提灯の芯が画面で最も明るい白に近い点。暖色の光が全体を包む
- 棚の酒瓶、吊るした植物、品書きの木札まで、あらゆる面に情報が詰まっている
- 無情報の黒い平面が画面に存在しない

**ペルソナ5 — 全UIが目指す基準**
- 支配色が1色（赤）で画面の大半を占め、白と黒だけが従う。第3の色を出さない
- 見出しは本文の3〜4倍。傾いた黒板に白抜きで叩き込む
- 選択中は「面が反転」して暗色の文字が乗る。枠線の太さで状態を表さない
- 画面の隅々まで要素で埋まり、無情報の平面が1cmも無い

**この4枚に共通する、機械的に測れる合格条件**
1. 画面のどの帯にも「行平均輝度が13未満の死に領域」が100px以上続かないこと
2. 画面に輝度245超のハイライトが必ず存在すること（ただし面積は1%未満）
3. 同一フレーム内のピクセル密度（1テクセルあたりの画面px）のばらつきが±20%以内
4. 文字サイズの段数が5段以内。ドット字体は設計グリッドの整数倍でのみ使う
5. 有彩色は「識別色1つ＋状態色（危険/成功）」に限る。色相12%超が3系統以上あれば不合格

## 使う前の準備：ベンチ画像

真のブラインド比較には実画像が要る。`docs/Refs/bench/` に以下を置く（手動で入れてよい）。

| ファイル名 | 何の画像か | 対応項目 |
| --- | --- | --- |
| `octopath2_town_night.png` | オクトパスIIの夜の街 | A, B |
| `octopath2_battle.png` | オクトパスIIの戦闘 | E |
| `dave_restaurant.png` | デイブの夜の店 | G |
| `p5r_menu.png` | ペルソナ5のメニュー | C, D, H |

画像が無い項目は、批評エージェントに「ベンチ画像なし・記憶依存の判定である」と
報告させる。記憶依存の判定は必ず甘くなるので、合格の根拠にはしない。

## 補足：なぜ「別人格の批評家」が要るか

実装したエージェント自身は、自分が直した箇所を無意識に高く評価する。批評役を分け、
どちらが自作か伏せて聞くことで、その補正が効かなくなる。ブラインドを外すと
「よくできています」に収束するので、A/Bのシャッフルは進行役が必ず行う。
